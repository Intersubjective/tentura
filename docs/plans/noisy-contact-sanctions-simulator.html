Симулятор рёбер доверия

Как Тентура превращает evidence из ledger в вес ребра для MeritRank, и что MR делает с этим весом в цепочке A → B → C. Модель повторяет trust_fold_pair (m0202), trust_project_pair (m0207), расписание проекций, шлюз публикации с ε и семантику стен MR v0.11. Время в днях от начала сценария. Переключатель «Модель» выбирает проекцию: текущую (m0207), окно шума с иммунитетом по T_imm или стадии 0–2 из docs/plans/noisy-contact-sanctions-design.md. Модель из «сравнить с» всегда видна пунктиром на графиках веса и скоров.

Во времени

Что моделируется и где упрощено
  • Свёртка точно как trust_fold_pair: s_k = Σ count·decay, вклад вида mix·s/(k_sat+s), T — сумма по trust-видам плюс vouch; T_recent — только записи не старше окна и виды с иммунитетом; n_noisy = s_7 (с затуханием, без насыщения). Предложение: n_noisy = Σcount живых (не отозванных) noisy моложе окна шума, без затухания — три игнора держат стену всё окно, а не ~10 минут.
  • Проекция как m0207: ban → −1 (или 0 без стен); иначе стена −d, если T_recent < порога и есть уровень; иначе T; иначе 0. Стена заменяет доверие. Предложение: иммунитет считается по T_imm — вклады иммунных видов без окна свежести плюс vouch (виды 8/9 по-прежнему не дают иммунитета). Спящая связь с T_imm ≥ порога больше не стирается стеной: ребро остаётся T, как требует таблица отображения в спеке MR (§4) и инвариант «невидимый и распространяющийся негатив запрещён». Сценарий «Спящая связь + 3 игнора» показывает разницу.
  • Стадии 0–2 (docs/plans/noisy-contact-sanctions-design.md): сигнал — только «просмотрел, без отклика», «не моё» и, для совместимости сценариев, kind 7; «не открывал» не считается. Сигнал весит 1 − q (норма неотклика X). Стадия 0: стена по n₀ за окно; при T − долг > 0 и галке «локальна» она живёт только в приложении (ранжирование входящих X), в MR уходит T − долг. Стадия 1: уведомление отправителю, когда n₀ ≥ K, не чаще раза за окно. Стадия 2: каждый сигнал в течение срока уведомления добавляет долг Δ, «не моё» — всегда; долг затухает с полураспадом и вычитается из T, итог может уйти в минус (стена в рамке X). Отзыв сигнала (адресат всё же откликнулся) снимает и его долг. Не моделируются: бюджет отправителя по всем адресатам (Ostra), различие своих просьб и пересылок, посты.
  • Когда проекция реально пересчитывается: в момент события по паре (запись, отзыв, vouch, ban) и на каждом maintenance — только если строка user_trust_edge существует (она удаляется при target = 0 и prev = 0). Между проекциями MR видит старый вес.
  • Публикация: |target − prev| > ε, или смена знака, или любое изменение отрицательного веса. Издатель считается мгновенным (в жизни ~10 с).
  • MR: вместо Монте-Карло — точное матожидание. Блуждание продолжается с вероятностью α и идёт только по положительным рёбрам, доля = вес / сумма исходящих. Отрицательное ребро X→Y делает Y стеной лишь в системе отсчёта X: вход в Y обрывает блуждание с вероятностью d = min(|w|,1), оборванное блуждание не даёт кредита никому. У Тентуры λ = 0. Чужие стены на систему отсчёта A не влияют (R6).
  • «Остальные» — одна сводная вершина вне цепочки. ρ — вероятность, что шаг из неё ведёт к следующему персонажу (косвенный путь). Без них в вырожденной цепочке нормировка делает любой положительный вес равным 1.
