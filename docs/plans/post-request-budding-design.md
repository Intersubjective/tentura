**Статус:** rev 1 (2026-10-11), решения владельца приняты (§2). §7 (шум и абьюз): N1–N6 решены.
Не план имплементации.
**Тикет на приватные отметки о пользе (D6):** #282.
**Архитектура:** [`post-request-budding-architecture.md`](post-request-budding-architecture.md) · **план реализации:** [`post-request-budding-implementation-plan.md`](post-request-budding-implementation-plan.md).

## 1. Суть

Запрос не «превращается» из поста, а **отпочковывается** от него: из сообщения поста создаётся
дочерний Запрос (`parent_beacon_id` = пост), пост продолжает жить. Это механика child-request
promotion из General, которая уже есть у Запросов (футер на исходном сообщении, hierarchy notice,
один дочерний Запрос на сообщение).

Почему не перенос/закрытие (#250):
- перенос истории выносит чужие реплики к другой аудитории (контекстуальная целостность);
- закрытие по умолчанию отнимает пространство у невыбранных (травма исключения);
- необратимость: отменённый Запрос в модели #250 оставляет мёртвый разговор;
- из одного разговора может вырасти несколько нужд, в том числе чужих.

Точки входа не объединяются: посты создаются во вкладке постов, Запросы — во вкладке Запросов
(как сейчас). Отпочкование — дополнительный путь создания Запроса.

## 2. Решения владельца (2026-10-11)

| # | Вопрос | Решение |
|---|---|---|
| D1 | Модель | Отпочкование (дочерний Запрос), пост живёт дальше |
| D2 | Q10 «у постов нет детей» и A7 «пост не даёт общего контекста» | Пересматриваются: у поста могут быть дочерние Запросы; участники поста — наблюдатели дочернего Запроса (видят содержание, не чат); автор Запроса может позвать соучастников поста |
| D3 | Кто может отпочковать | Любой участник поста, от своего сообщения; он становится автором Запроса |
| D4 | Заслуга за маршрут | Наследуется: путь, которым позванный пришёл в пост, засчитывается пересылкам как путь к помощнику |
| D5 | Предотметка в списке позванных | Эвристика: отмечены те, кого автор упоминал или кто отвечал по делу; предупреждение, если отмечено больше N |
| D6 | «Польза» из поста | Не переносится и не учитывается. Советчика можно односторонне добавить в друзья. Приватные отметки о пользе — отдельная фича позже (тикет) |
| D7 | Принцип допуска (для всех Запросов) | **Два подтверждения на любой допуск**: одно от автора, одно от помощника (§3) |

## 3. Принцип допуска: два подтверждения

Допуск в Запрос (room access + стейк) требует ровно двух согласий:

| Путь | Подтверждение автора | Подтверждение помощника |
|---|---|---|
| Автор лично позвал (прямая пересылка автором, приглашение из поста) | само приглашение | «Принять» |
| Помощник сам предложил помощь (после пересылки третьим лицом, discoverable, общий контекст) | подтверждение предложения (`useful` / `needCoordination`) | само предложение |

Следствия:
- Принятие личного приглашения = предложение + подтверждение атомарно; человек сразу committer.
- Никто не попадает в Запрос без собственного согласия (это и был баг #239).
- Отказ от приглашения тихий, без стейка; автор видит «не сможет», остальные — ничего.
- Стюарды — прежнее осознанное исключение (доступ без стейка).

**Уточнение владельца (2026-10-11):** пересылка автором **не** является подтверждением автора —
предложение помощи после неё по-прежнему требует accept (контроль автора; рассылка «кто может?»
не открывает чат). Подтверждением автора служит только явный выбор человека при отпочковании от поста.

## 4. Статусы людей в дочернем Запросе

| Кто | Статус | Механика |
|---|---|---|
| Позванные автором | приглашение (автор уже подтвердил) | «Принять» → committer; «Не смогу» → остаётся в посте |
| Остальные участники поста | наблюдатели: содержание да, чат нет | могут «Предложить помощь» обычным путём; пушей нет |
| Пришедшие по пересылке Запроса | как сейчас | без изменений |

## 5. Поток

1. **Вход:** кнопка в шапке/⋯ поста и действие на сообщении. Подпись «Оформить запрос».
2. **Форма Запроса** предзаполнена исходным сообщением. Цитировать можно только свои сообщения.
3. **Кого позвать:** участники поста, писавшие — выше; вышедшие («Не интересно») и заблокированные
   скрыты; незнакомые автору помечены «через X». Предотметка — D5. Личная приписка к приглашению.
   Соучастники поста доступны для приглашения, даже если по видимости/MR автор их иначе не позвал бы.
4. **Аудитория:** discoverable по умолчанию **выключен** с предупреждением; если в посте пересылка
   была выключена — предупреждение, что Запрос пересылать можно.
5. **Уведомления:** позванным — приглашение как предложение в «Активности → Для вас» (не обязательство: до принятия Запрос не в зоне ответственности; см. §7, S6); остальным — без пушей,
   только системная карточка в посте: «оформил(а) запрос «…», позвал(а) N человек» (число, без имён).
6. **Пост:** чекбокс «Закрыть пост и продолжить в запросе»; по умолчанию включён, только если
   позваны все или в посте ≤ 2 человек. Иначе пост затухает по своему окну активности (72 ч).
7. **Поле:** Запрос наследует якорь поста; если пост не закрыт — тонкая связь «выросло из».
8. **Жизненный цикл:** закрытие/отмена Запроса → hierarchy notice в посте. Удаление поста (в т.ч.
   через удаление корневого сообщения, R4-3) не каскадирует в Запрос: tombstone-ссылка.
9. **Миграция:** ранее сконвертированные in-place Запросы — разовая чистка, без совместимости
   (legacy-клиентов нет).

## 6. Доверие

- Заслуга за маршрут наследуется (D4).
- Польза в посте не учитывается (D6).
- Взаимодействие приглашений из поста со стеной за шум — §7.

## 7. Шум и абьюз

Обсуждение 2026-10-11; общий дизайн санкций — [`noisy-contact-sanctions-design.md`](noisy-contact-sanctions-design.md)
(стена сейчас выключена глобально, R3; сигналы пишутся в ledger).

**Решено (2026-10-11):**
- **N1 (S1, S2). Кого можно звать в обход видимости:** соучастников поста, которые **писали в посте
  или ставили реакции**. Молчаливые участники — только по обычным правилам видимости/пересылки.
  Парное взаимодействие отвергнуто: его трудно объяснить. Тот же признак делает приглашение «тёплым».
- **N2 (S5). Ответы на приглашение:** без новых кнопок («не моё» / «не зовите»). Учёт для стены —
  как у пересылок Запросов сейчас (отказ без evidence, отклик = engaged).
- **N3 (S7). Наблюдатели дочернего Запроса:** снимок участников поста на момент отпочкования,
  без пополнения новыми участниками поста.
- **N4 (S6). Приглашение — предложение в «Активность → Для вас»,** не обязательство.

- **N5 (S3).** Не больше одного ожидающего приглашения от одного автора одному человеку из одного
  поста; повторные приглашения сворачиваются в одно.
- **N6 (S4).** Системное сообщение «оформил(а) запрос «…», позвал(а) N человек» в чате поста видят
  **все** участники поста, кто бы ни оформил Запрос — автор поста или другой участник.

**Без решения (не требуется сейчас):**
- S8 (накрутка через наследование пути): новой поверхности нет, общая sybil-проблема MR.
- Бюджет отправителя (Q8 дизайна шума): приглашения тратят тот же бюджет, что пересылки; по стадиям роста.
