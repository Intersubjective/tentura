# План запроса («либретто»): макеты, ревизия 1

Тикет: #220 «Сценарии для участников и текущий шаг». Черновик для обсуждения, 4 октября 2026.

## Откуда взяты приёмы

| Область | Приём | Где у нас |
|---|---|---|
| Театр (помреж, cue calling) | Две команды: **«Внимание»** (standby) и **«Пошёл»** (go). Актёр всегда знает текущую реплику и следующую. | YOU: строка «СЕЙЧАС» + строка «ДАЛЬШЕ» (тетрис) |
| Армия (OPORD, sync matrix) | Матрица синхронизации: строки люди, столбцы время. Подтверждение приказа («принял»). | Вид «По людям»; кнопка «Понял» при изменении твоего шага |
| Медицина катастроф (ICS 204) | Лист назначений: у каждой задачи ровно один ответственный. Доска статусов: цвет только для отклонений. | Один исполнитель на шаг; красный только для просрочки |
| Доставка (курьерские приложения) | Текущая остановка крупно, следующая мелко, ETA, «опаздываешь» прямо на карточке. | Карточка шага с временем и «+15 мин» |
| Кино (call sheet) | Один лист на день, сгруппированный по времени, «линия сейчас». | Экран плана с красной линией текущего времени |
| Календари | Линия «сейчас», которая сама сдвигается. | Там же |

Главный принцип: **человек, открывший запрос, за 2 секунды видит, что делать ему сейчас и что будет следующим.** Весь план нужен реже, в основном автору и тому, кто правит.

## 1. HUD: как это выглядит у участника (Иван)

```
┌──────────────────────────────────┐
│ ←  Грядки для Elm Street      ⋮  │
│    ● Идёт · до сб 18:00 (2 дн)   │
│  [Now]   Plan   Chat 4   People  │
╞══════════════════════════════════╡
│ ▶ ТЫ  Привезти доски       10:00 │
│       к школе, ворота с Elm      │
│       [ Готово ]  [ Не успеваю ] │
│   ДАЛЬШЕ  Собрать каркас  11:30  │
│ ⚑ СЕЙЧАС  09:40 Ольга открывает  │
│           склад · по плану       │
│ 👥 3/4  ▤ план 4/9  ⏰ 1  📌 2    │
╞══════════════════════════════════╡
│ …                                │
```

- **ТЫ** = «Пошёл»: твой текущий шаг плана, крупно, с временем и действием прямо в строке.
- **ДАЛЬШЕ** = «Внимание», как следующая фигура в тетрисе: одна строка, приглушённо, без кнопок. Если следующего нет, строки нет.
- **СЕЙЧАС** (бывший «ШАГ» / NOW): что происходит в запросе по времени. Пометка «по плану» говорит, что строку поставил план, а не человек.
- Счётчик «▤ план 4/9» = выполнено 4 из 9 шагов, тап открывает вкладку Plan.

### 1a. Системное уведомление важнее плана

```
│ ▶ ТЫ  Рассмотри 2 предложения    │
│       [ Открыть ]                │
│   ПО ПЛАНУ  Привезти доски 10:00 │
│   ДАЛЬШЕ    Собрать каркас 11:30 │
```

Шаг плана не пропадает, а опускается на строку «ПО ПЛАНУ». Когда уведомление разобрано, шаг поднимается обратно в «ТЫ».

### 1b. Твой шаг ещё не наступил

```
│ ▶ ТЫ  Свободен до 11:30          │
│   ДАЛЬШЕ  Собрать каркас  11:30  │
│           через 1 ч 50 мин       │
```

Правило «текущего шага» для человека: первый невыполненный его шаг, у которого время начала наступило или не задано. Если ближайший шаг в будущем, показываем «Свободен до …».

### 1c. Опаздываешь

```
│ ▶ ТЫ  Привезти доски  ⏰ +25 мин  │
│       должно было быть к 10:00   │
│       [ Готово ]  [ Не успеваю ] │
```

Красный только здесь. «Не успеваю» открывает выбор: «перенести на…», «передать другому», «написать в чат». Любой вариант правит план и попадает в историю.

### 1d. План изменили, и это касается тебя

```
│ ▶ ТЫ  Привезти доски  10:00→11:00│
│       Ольга перенесла 3 мин назад│
│       [ Понял ]                  │
```

Как «принял» в армии: пока человек не нажал «Понял», изменение висит наверху. Автор видит, кто подтвердил (см. 4).

## 2. NOW: строка «СЕЙЧАС» по времени

```
09:12  Ольга вручную: «ждём Ивана с досками»
       ⚑ СЕЙЧАС  Ждём Ивана с досками
                 Ольга · 09:12          ✎

10:00  Наступило время шага 3, строка заменилась
       ⚑ СЕЙЧАС  10:00 Иван везёт доски
                 по плану · шаг 3/9     ✎

10:07  Иван вручную: «застрял в пробке»
       ⚑ СЕЙЧАС  Застрял в пробке
                 Иван · 10:07           ✎
```

Правило: «последний пишущий выигрывает», и наступление времени шага считается записью. Ручная правка не отменяет план, она просто новее.

## 3. Вкладка Plan: «либретто»

```
┌──────────────────────────────────┐
│  Now  [Plan]   Chat 4   People   │
│ ПЛАН · 4/9 · правка Ольги 10 мин │
│ [Все ▾]  [Мои]       История  ✎  │
├──────────────────────────────────┤
│ СБ 12 ОКТ                        │
│ ✓ 08:30  (ОЛ) Купить саморезы    │
│ ✓ 09:00  (ПН) Согласовать с      │
│               директором         │
│ ✓ 09:40  (ОЛ) Открыть склад      │
│ ━━━━━━━━━━━━ 10:20 сейчас ━━━━━━━ │
│ ⏰ 10:00  (ИВ) Привезти доски      │
│           +20 мин                │
│ ☐ 11:30  (ИВ) Собрать каркас     │
│      –13:00                      │
│ ☐ 13:00  (МК) Обед на всех       │
│ ☐  —     (ПН) Фото для отчёта    │
│ ВС 13 ОКТ                        │
│ ☐ 10:00  (ОЛ) Полить грядки      │
│ ☐  —     ( ?) Вернуть тачку      │
│          нет исполнителя         │
└──────────────────────────────────┘
```

- Порядок строк = порядок плана. Время необязательно, «—» значит «после предыдущего».
- Линия «сейчас» стоит между прошлым и будущим и сдвигается сама.
- Выполненное приглушено, но не прячется: видно, что уже сделано.
- Шаг без исполнителя помечен, это пробел в плане, автору заметно сразу.
- «Мои» оставляет только твои шаги, но с соседними шагами других тусклыми (чтобы видеть, после кого ты).
- Галку ставит исполнитель тапом по ☐. Другие участники тоже могут, тогда рядом «отметила Ольга».

### 3a. Вид «По людям» (широкий экран, планшет, повёрнутый телефон)

```
            08    09    10    11    12    13
ОЛЬГА      [✓саморезы][✓склад]
ИВАН                     [⏰доски][каркас────]
МАРИЯ                                  [обед]
ПРИЯ             [✓директор]
                         ┃ сейчас
```

Матрица синхронизации: сразу видно, кто перегружен и где дыры. На узком телефоне этот вид не показываем.

## 4. Карточка шага (тап по строке)

```
┌──────────────────────────────────┐
│ Шаг 4 из 9                    ✕  │
│ Привезти доски                   │
│ к школе, ворота с Elm, 12 шт     │
│ (ИВ) Иван     сб 10:00 – 10:30   │
│ ⏰ опаздывает на 20 мин           │
│ Подтвердил изменение: ✓ 09:15    │
│ ───────────────────────────────  │
│ [ Готово ] [ Перенести ] [ ⋯ ]   │
│ Обсудить в чате ›                │
└──────────────────────────────────┘
```

«Обсудить в чате» создаёт сообщение со ссылкой на шаг (как сейчас цитируются факты).

## 5. Редактирование

```
┌──────────────────────────────────┐
│ ✕  Правка плана        Сохранить │
├──────────────────────────────────┤
│ ≡ ✓ 08:30 (ОЛ) Купить саморезы   │
│ ≡ ☐ 10:00 (ИВ) Привезти доски    │
│ ≡ ☐ 11:30 (ИВ) Собрать каркас    │
│ ≡ ☐ 13:00 (МК) Обед на всех      │
│ ＋ Добавить шаг                   │
├──────────────────────────────────┤
│ Что поменял (необязательно):     │
│ [ перенесли каркас из-за дождя ] │
└──────────────────────────────────┘
```

- ≡ перетаскивание меняет порядок; тап по строке открывает поля (текст, исполнитель, начало, конец).
- Правка сохраняется одной ревизией целиком, как черновик: участники не видят полуготовое.
- Если пока ты правил, кто-то другой сохранил свою версию: показываем «Ольга успела поменять 2 шага» и сливаем построчно, конфликт только если оба трогали один и тот же шаг.

## 6. История правок

```
┌──────────────────────────────────┐
│ ←  История плана                 │
├──────────────────────────────────┤
│ 10:10  Ольга · «из-за дождя»     │
│   ~ Собрать каркас 11:00 → 11:30 │
│   + Полить грядки (вс 10:00, ОЛ) │
│ 09:15  Прия                     │
│   ~ Привезти доски: Мария → Иван │
│   – Купить краску                │
│ вчера  Прия · создала план       │
│                [ Вернуть эту ]   │
└──────────────────────────────────┘
```

Как у фактов сейчас: каждая ревизия видна, любую можно вернуть (возврат тоже ревизия). Галки «выполнено» в историю правок не идут, иначе она утонет в отметках; они видны в чате системными строками (раздел 11).

```

│ Плана пока нет.                  │

│ когда, и каждый увидит свой шаг. │

```

## 8. My Work: субкарточки шагов плана

Шаги плана встают в существующий блок обязательств карточки (тот же, где сейчас «ответьте на предложение»). Шаг твой и ждёт тебя, значит это обязательство: у строки есть действие и нет ×, потому что скрыть его молча значит соврать тем, кто ждёт.

```
┌──────────────────────────────────┐
│ (ПН) Грядки для Elm Street    ⋮  │
│      ● Идёт · сб 18:00           │
│ ⚑ 10:00 Иван везёт доски         │
├──────────────────────────────────┤
│ ▤ 10:00  Привезти доски  ⏰ +20м  │
│          [ Готово ] [Не успеваю] │
│ ▤ 11:30  Собрать каркас     ДАЛЬШЕ│
└──────────────────────────────────┘
```

- Первая субкарточка: текущий шаг, с действиями. Вторая: следующий шаг, тусклая, без кнопок, как в тетрисе.
- Строка ⚑ под заголовком = СЕЙЧАС запроса, она уже есть на карточке (`roomCurrentLine`) и по времени заменяется шагом плана так же, как в HUD.

### 8a. Изменение твоего шага (ждёт «Понял»)

```
├──────────────────────────────────┤
│ ✎ Ольга перенесла твой шаг       │
│   «Привезти доски» 10:00 → 11:00 │
│                       [ Понял ]  │
│ ▤ 11:00  Привезти доски          │
```

Пока не нажал «Понял», эта строка первая. После нажатия остаётся обычная субкарточка шага.

### 8b. Шаги есть, но не скоро

```
├──────────────────────────────────┤
│ ▤ сб 11:30  Собрать каркас       │
│             через 2 дня          │
```

Одна тусклая строка. Без кнопок, не считается «требует внимания» и не поднимает карточку в сортировке.

### 8c. Сортировка и фильтр My Work

- Карточка с наступившим или просроченным шагом поднимается наверх, как сейчас поднимаются карточки с обязательствами.
- Счётчик внимания на вкладке считает: наступивший шаг, просроченный шаг, непринятое изменение. Будущие шаги не считает.

## 9. Уведомления

Раскладываем события плана по категориям, которые уже есть в настройках уведомлений:

| Событие | Кому | Категория | Push |
|---|---|---|---|
| Через 15 мин начинается твой шаг | исполнителю | Просьбы к вам | да |
| Твой шаг наступил (время начала) | исполнителю | Просьбы к вам | да |
| Предыдущий шаг выполнен, теперь твой (шаг без времени) | исполнителю | Разблокировки | да |
| Твой шаг перенесли, передали тебе или забрали | исполнителю | Просьбы к вам | да, с «Понял» |
| Твой шаг просрочен (прошло время конца) | исполнителю | Просьбы к вам | да, один раз |
| Шаг просрочен на 30 мин | автору запроса | Координация | да, один раз |
| Кто-то нажал «Не успеваю» | автору | Координация | да |
| План правили, тебя не касается | всем | Второстепенное | нет, только лента |
| Кто-то отметил шаг выполненным | всем | Второстепенное | нет |

Правило Вадима (4 окт): **в For You попадает только то, что можно пропустить без последствий** для других и для своей репутации. Поэтому события, которые требуют от человека действия (шаг наступил, просрочен, твой шаг изменили, твой ход), в For You **никогда** не идут: они живут в YOU, My Work, NOW и push. В For You могут попасть только строки «План правили, тебя не касается» и «кто-то отметил шаг».

Правила, чтобы не заспамить:
- Одна правка плана = одно уведомление на человека, даже если поменялось пять его шагов («Ольга изменила 3 твоих шага»).
- Напоминание «через 15 мин» не шлём, если шаг уже отмечен или человек сейчас в этом запросе.
- Просрочку напоминаем один раз, без повторов.

## 10. Копирование запроса вместе с планом

Копирования запроса в коде сейчас нет (поиск по client не нашёл ни кнопки, ни строк), так что это новая функция. План копируется как сценарий-заготовка: порядок, тексты и длительности переносятся, а отметки, история и люди остаются в старом запросе.

```
┌──────────────────────────────────┐
│ ✕  Новый запрос из копии         │
│    «Грядки для Elm Street»       │
├──────────────────────────────────┤
│ Название                         │
│ [ Грядки для Elm Street (копия) ]│
│ ПЛАН · 9 шагов                   │
│ Начало первого шага              │
│ [ сб 19 окт ] [ 08:30 ]          │
│ все шаги сдвинутся на +7 дн      │
│                                  │
│ 08:30  ( ?) Купить саморезы      │
│        было: Ольга  [ позвать ]  │
│ 10:00  ( ?) Привезти доски       │
│        было: Иван   [ позвать ]  │
│ …ещё 7                           │
│ [ Создать ]                      │
└──────────────────────────────────┘
```

- **Время:** сохраняются интервалы между шагами и длительности, весь план сдвигается к новой дате начала одним полем.
- **Галки** сбрасываются, **история правок** начинается заново с ревизии «скопирован из …».
- **Исполнители:** в новом запросе ещё нет команды, поэтому шаги без исполнителя, с подсказкой «было: Иван» и кнопкой «позвать» (переслать ему запрос). Когда человека впустят, шаг назначается на него автоматически.

## 11. Обновления плана системными строками в чате

Изменения плана попадают в чат запроса тонкими системными строками. Чат уже умеет показывать системные строки событий у элементов координации (`room_message_tile.dart`), так что это тот же механизм.

```
│ (ОЛ) Ольга                 09:58 │
│ Склад открыт, доски у ворот      │
│                                  │
│ ── ▤ Ольга изменила план ─ 10:10 │
│    ~ Собрать каркас 11:00→11:30  │
│    + Полить грядки (вс, Ольга)   │
│    «из-за дождя»     История ›   │
│ ── ✓ Иван: Привезти доски  10:31 │
│ ── ⏰ Иван не успевает: Собрать   │
│    каркас → перенёс на 12:00     │
│                                  │
│ (ИВ) Иван                  10:33 │
│ Ребята, пробка на мосту          │
```

Что пишем в чат:
- **Правка плана:** одна строка на ревизию со списком изменений (до 3, дальше «ещё N») и комментарием автора правки. Тап открывает историю на этой ревизии.
- **Шаг выполнен:** «✓ Иван: Привезти доски», а если отметил другой участник, то «✓ Ольга отметила за Ивана: …». Несколько отметок подряд без сообщений между ними склеиваются в одну строку «✓ 3 шага выполнено».
- **«Не успеваю»:** строка с выбранным вариантом (перенёс, передал Марии). Вариант «написать в чат» даёт обычное сообщение человека со ссылкой на шаг.
- **Копия плана:** первая строка в чате нового запроса: «План скопирован из „…“».

Что в чат **не** пишем, чтобы не засорять: наступление времени шага (это видно в NOW), напоминания, «Понял».

## Что уже есть в коде и на что это ляжет

- **Факты уже под контролем правок**: таблица `beacon_fact_card_revision` (seq, actor, kind, restoredFromSeq), миграции m0199/m0200. Это линейная история снимков с возвратом. Для плана можно сделать так же, отдельной библиотеки не нужно, если правки не одновременные.
- **Пункты координации** (`coordination_item`): у них уже есть исполнитель (`targetPersonId` / `acceptedById`), порядок (`ordering`), статус и `resolvedAt`. Шаг плана очень похож на пункт координации с временем.
- **YOU** сейчас берётся из `beacon_participant.nextMoveText` и системных состояний; **NOW** из `beacon_room_state.currentLine`.

## Вопросы на решение (по одному)

1. ~~Шаг плана = вид пункта координации или отдельная сущность?~~ **Решено (Вадим, 4 окт):** элементы координации из UI приложения уже убраны, поэтому таблицу `coordination_item` переиспользуем под шаги плана.
2. ~~Кто ставит галку за другого?~~ **Решено (Вадим, 4 окт):** любой участник, с подписью «отметила Ольга».
3. ~~Нужно ли «Понял» при изменении твоего шага?~~ **Решено (Вадим, 4 окт):** да, изменение висит в ТЫ до «Понял», автор видит, кто подтвердил.
4. ~~Одновременная правка?~~ **Решено (Вадим, 4 окт):** свои ревизии: черновик правки, слияние по шагам, конфликт только если двое правили один шаг. Без CRDT-библиотеки.
5. ~~«Не успеваю»: что предлагаем?~~ **Решено (Вадим, 4 окт):** три варианта: перенести на…, передать другому, написать в чат.
6. ~~Вид «По людям» в первой версии?~~ **Решено (Вадим, 4 окт):** да, сразу (широкий экран и повёрнутый телефон).
7. ~~За сколько напоминать о начале шага?~~ **Решено (Вадим, 4 окт):** 15 минут, без настройки в первой версии.
8. ~~Кнопки «Готово» и «Понял» прямо в push?~~ **Решено (Вадим, 4 окт):** да.
9. ~~Копия: назначать шаг прежнему исполнителю?~~ **Пересмотрено (Вадим, 5 окт):** при копировании назначения полностью сбрасываются, без «было: X» и автоназначения. Назначать шаг можно только на допущенного в запрос.
