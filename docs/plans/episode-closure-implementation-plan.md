# Закрытие эпизода и обновление доверия — план реализации

**Status:** draft, rev 22. Ждёт утверждения.

**Дата:** 2026-09-28

**Основание:** `post-request-closure-social-design.md` (rev 3, D1–D22, §17.4). Здесь не пересказывается, почему устроено именно так; этот план — как построить.

**Связанные:** `subjective-help-tag-evidence-architecture.md` (close-ack как outcome evidence, D16/D19) · `~/MY_SRC/meritrank-rust/NEGATIVE_EDGES_FEATURE.md` (реализовано в service v0.11.0 / core 0.12.0) · `received-reviews-trust-changes-plan.md` (#107 — отменяется целиком этим планом).

**Рамки выкатки:** пользователей нет, только тестеры; клиент только web. Старая совместимость не строится: одна выкатка, после неё поднимается `kDefaultMinClientVersion`. Старые данные отзывов и доверия удаляются.

## 0. Резюме

Три фазы.

- **Фаза 0 (срочно, отдельный PR).** Tentura уже на MR v0.11.0, где отрицательный вес — это стена, а TT до сих пор публикует знаковый `trust_edge_weight`. Каждый плохой отзыв сейчас стоит стеной (при λ=0 стена только не начисляет доверие). Нужно обрезать вес до ≥0 и заново опубликовать все рёбра.
- **Фаза A — новое закрытие.**
  - Пятибалльный отзыв о людях удаляется целиком.
  - Автор отмечает исход по каждому принятому офферу, сам распределяет половину итогов запроса и пишет рассказ.
  - Помощники в это же время могут закрыто разделить вторую половину между коллегами, чью работу видели (беспристрастный делёж).
  - Каждый может в один клик поставить 🔖 — приватную закладку, которая строит личное ребро и никому не показывается.
  - Доверие собирается из корзин по типам событий, а не из знаковых корзин валентности.
- **Фаза B — стены.**
  - Бан публикуется как −1.
  - Появляется стена «ты шумишь» из неразрешённых форвардов.
  - Сторона «я его дёргал» становится множителем при показе.
  - Добавляются барьер `mr_sync` и бутстрап стен.
  - λ остаётся 0 до симуляции.

Фаза C (переприглашение с поправкой на ранжирование, σ, тревога поручителю, заявление о несоответствии, наследование стен) и защита чтения от утечек в этот план не входят (§12).

## 1. Принятые решения

### 1.1 UX закрытия (решения владельца, 2026-09-28)

| # | Решение |
|---|---|
| **U1** | Личных чатов в Tentura нет. В закрытии **нет никакого текста конкретному человеку** (записок нет, U38). Публичный текст — только рассказ о закрытии |
| **U3** | Поддержать (U47) можно **любого члена эпохи**, включая тех, у кого автор отметил «Не выполнено», и ушедших (U41). Поднять такого — допустимо (U42) |
| **U4** | Переход в состояние оценки (`BeaconStatus.reviewOpen`) открывает сразу два процесса: автор отмечает исходы и распределяет свою половину; помощники по желанию отмечают коллег (U47). Закладки доступны всем на тех же экранах |
| **U5** | Дедлайн оценки и авто-закрытие работают как сейчас: 7 дней, продления, sweep по истечении. Исход, на который автор не ответил, при авто-закрытии считается «Не могу судить» (U55): человек остаётся в равной доле автора, close-ack не пишется |
| **U6** | Если автор не начал закрытие, помощник может у себя отправить запрос в архив. Эффекта на доверие нет, это только скрытие из списков |
| **U7** | Автору **раз в неделю** приходит напоминание о «протухшем» запросе. Протухший = статус из открытой семьи и (срок `end_at` прошёл **или** N дней без активности) |
| **U9** | Экран дележа видят **все** одобренные помощники: в момент выбора никто не знает, что решит автор |
| **U11** | Ребро H→F («мне прислали стоящее») ставится **автоматически** при одобрении оффера и **снимается только при добровольном уходе** помощника (U41) |
| **U12** | Переоткрытие отменяет всё. Введённые данные (исходы, распределение автора, поддержка коллег, закладки, рассказ) **сохраняются и предзаполняются** при следующем закрытии; отметки коллег после reopen снова нужно подтвердить «Готово» |
| **U13** | Рассказ о закрытии **опционален** |
| **U14** | Бюджет эпизода **фиксирован** (Q1 = вариант а). Если автор отметил «Не выполнено» всем, помощникам ничего не чеканится. Закладки записываются **независимо** от решения автора |
| **U15** | Цепочке платят за одобренного помощника, независимо от исхода (Q2 закрыт решением §11 записки) |
| **U16** | Доверие строится из **корзин по типам событий** («помог», «полезный форвард», «закладка», «шумел», …). У каждой корзины своё затухание и насыщение; корзины смешиваются с весами и сворачиваются в ребро. Категориальная шкала валентности уходит |
| **U17** | Утечки на стороне чтения (`graph()` с `positive_only` от клиента, `graph_edges_between`, оракулы) **в этом плане не чинятся** |
| **U18** | Напоминание о протухшем запросе шлётся автору **даже если помощников никогда не было** |
| **U19** | Вовлечение в форвард = **оффер** на этот запрос или **форвард дальше**. **Watching нейтрален** (ревью: из вежливости его нажимали бы ради спокойного завершения контакта). «Не могу помочь» нейтрально |
| **U20** | На экране помощника за кнопкой (i) — **визуальная схема** с реальными аватарами: половину распределяет автор, половину — коллеги; твоя отметка сдвигает только твой срез между другими и на твою часть не влияет. Потоки к другим — серые одинаковые полосы с подписью «пример», не реальные решения автора (A11). Под схемой — текст «Ты не знаешь, как решил автор, — и знать не нужно. Поддержи тех, чья работа, по-твоему, была важной. Если автор уже оценил человека высоко, добавка будет маленькой; если низко — заметной. Отдают в основном те, кому автор дал больше. Автор твой выбор не видит» |
| **U23** | Ферма ссылок в MR не работает: попадания дедуплицируются внутри забега. Ограничение проверяется как **доля сдвига рамки**, а не как «эмиссия» |
| **U28** | **Двое помощников: доли назначает автор** — слайдер соотношения (частный случай U34 с `α = 1`). Копирайт честный: «Каждый увидит свою долю — а значит, и долю другого». Исключение из D9/D12 записки осознанное |
| **U34** | **Автор участвует в дележе как главный свидетель.** Автор распределяет `α_A = 50%` пула помощников между «Выполнено» и «Не могу судить» (`A`, U55) (слайдеры, шаг 5%, по умолчанию ровно поровну, минимум 5% каждому в `A` — U50). Слайдеры заблокированы до «Изменить распределение», рядом — предпросмотр «если коллеги промолчат, получится примерно так» (полосами). Остальные `1 − α_A` помощники делят беспристрастно (U47). При `|M| = 2` автор распределяет 100% (U28), при `|M| = 1` — весь пул одному, если подтверждён |
| **U35** | ~~«Видел» + ползунки~~ — **заменено U47**: одна кнопка «Поддержать» |
| **U36** | **Видимость результата.** Каждый помощник видит только **свой** итог — словами относительно молчания коллег (U48) — и исход автора по себе. Кто кому что отметил, приложение не показывает никому, включая автора (автор видит только своё распределение), и полного распределения не показывает; API отдаёт только код полосы, не число (U57). Обещание в интерфейсе: «В приложении твой выбор не видят. По своим итогам другие могут о нём догадаться» |
| **U37** | **Закладка 🔖** — полностью субъективная, никому не показываемая, опциональная, в один клик. Смысл: «в этом эпизоде я испытал к этому человеку благодарность — пусть моё ребро к нему в сети немного усилится». Отметить можно других помощников и автора (помощнику) или помощников (автору). Бамп в корзину `marked` (вес 0.2, §3.2). Цели не показывается, записки нет, от доли и решения автора не зависит. **Ставить и снимать можно свободно и после закрытия** (исключение из U40); дата для затухания — дата закрытия запроса. Копирайт: «Закладка чуть усиливает твою связь с этим человеком в сети. Ему не придёт уведомление, части в этом запросе не меняются. Поставить и снять можно и позже» |
| **U38** | **Явного «спасибо» нет.** Сняты: спасибо автора и помощников, оплата из доли, приоритеты, передача части полученного, записки, лента «Мне сказали спасибо». Не согласиться с распределением автора помощники могут своей половиной дележа (без гарантии, что это «восстановит справедливость»: молчание отдаёт голос автору); информацию для личных рёбер собирает закладка U37 |
| **U39** | **Иммунитет от стены «шумит» — только по свежему доверию.** Стена не публикуется, если `T_recent ≥ τ_imm` (0.05), где `T_recent` считается по активной подписке `vouch` и свидетельствам **не старше 180 дней**; старые свидетельства в иммунитете не участвуют (в обычном `T` участвуют). Коэффициенты подбираются потом на живой базе или модели (§3.2.2) |
| **U40** | **Один раунд вслепую.** Все решения (исходы, распределение автора, голоса, метки) принимаются одновременно и запечатанно в окне оценки. **Поправки после закрытия нет** — ни у автора, ни у помощников; единственное исключение — свои закладки, их можно ставить и снимать в любой момент (U37). Единственный откат — reopen до финализации (P10) |
| **U41** | **Ушедшие помощники учитываются.** Кто был одобрен, а потом ушёл сам или был исключён автором, остаётся членом эпохи: показывается **в конце списка** с нейтральной пометкой «не в запросе» (коллегам не показывается, кто инициатор; автор видит «ушёл» / «исключён»). Автор может отметить его исход и распределить ему часть; коллеги — отмечать его и ставить закладки. **Голосуют** только те, кто был активен при открытии оценки и не был исключён автором (U49); срез не голосующего всегда молчит и следует распределению автора. Свои закладки ставить может любой. **Ребро H→F и поток роутинга снимаются только при добровольном уходе** (детектор bait-and-switch, записка §11) |
| **U42** | Беспристрастная половина коллег может перевесить решение автора «не сделал» — это осознанно: коллеги видели работу, которую автор мог не заметить |
| **U43** | **Сговор пар принят.** Двое помощников, поднимающие друг друга, выигрывают за счёт третьего (при трёх равных: 37,5 / 37,5 / 25). Это свойство любого беспристрастного дележа: он защищает от собственного голоса, а не от коалиций; снаружи сговор неотличим от «мы видели работу друг друга». Дополнительных метаданных не пишем — пары видны в журнале свидетельств и парных корзинах; решение — долгосрочным анализом (§12). Полоса относительно молчания (U48) порогом ±15% скрывает сдвиг одной пары (+12,5%) |
| **U44** | **Одна кнопка «Готово».** Отметки коллег автосохраняются как черновик, но в расчёт идёт только **последняя подтверждённая «Готово» версия**. Рядом с кнопками всегда строка «В расчёте: поддержаны Иван, Оля» (или «В расчёт ещё не входит»); правка после «Готово» не отменяет учтённую версию: «На экране иначе — „Готово“ заменит расчёт». «Пропустить» при непустой учтённой версии спрашивает «Стереть то, что уже в расчёте?». Под кнопками оба условия досрочного закрытия: «Автор может закрыть после <время> — или раньше, когда ответят все». За 24 ч до закрытия — напоминание тем, у кого есть неучтённые изменения; в итогах — «твои отметки не вошли» или «в расчёте прошлая версия, последняя правка не вошла». Закладки — в один клик, без «Готово» |
| **U45** | **Вес голоса наполовину обеспечен автором** (`β = 0.5`). Срез помощника i: `(1−α)·pool_h·[β/n + (1−β)·a_i/100]` — половина голоса у всех равная, половина пропорциональна доле, которую ему назначил автор. Беспристрастность сохраняется (вес зависит только от решения автора). Голосуют только активные члены `V`; срез ушедшего всегда молчит (следует автору). Кольца тех, кого автор не признал, теряют половину силы; те, кого автор вывел «Не выполнено», сохраняют половину голоса; честный подъём неподтверждённого признанными коллегами усиливается. Сговор пар, признанных автором одинаково, не меняется (U43) |
| **U47** | **Одна кнопка у каждого коллеги: «Поддержать» (нажата / отжата).** По умолчанию все отжаты — «как решил автор». Нажатая — человек получает добавку; добавку отдают все отжатые. Прямо опустить кого-то нельзя: человек теряет, только если ты поддержал другого (для дележа с нулевой суммой это честно, и нет страха выглядеть доносчиком). После первого нажатия у строк появляются индикаторы направления без чисел: ▲ у поддержанных, ▼ у остальных, с подписью «▲ получат добавку — ▼ её отдадут те, кого ты не выбрал». Правило **монотонное**: поддержка никогда не даёт меньше, чем молчание. **Смысл** — не «спасибо» (его никто не видит) и не догадка о решении автора (раунд слепой, U40): помощник отмечает тех, **чья работа, по его мнению, была важной**, а поправку относительно автора правило делает само — добавка тем больше, чем ниже автор оценил человека относительно остальных, и отдают в основном те, кому автор дал больше (§4.2, «Знать решение автора не нужно»). Так недооценённые что-то получают и продолжают взаимодействие |
| **U48** | **Итог относительно молчания коллег.** «Коллеги подняли твою часть» / «как если бы коллеги промолчали» / «коллеги опустили твою часть» — сравнение с тем же эпизодом при молчании всех, порог ±15%. Точного своего числа нет, «поровну было бы X%» нет: неравный делёж автора не читается как оценка, а распределение автора не раскрывается. При `|M| ≤ 2` полосы нет. Если части нет (автор отметил «Не выполнено» и никто не поднял) — отдельная строка «Автор отметил: не выполнено — части в итогах нет», без слова «ниже» |
| **U49** | **Голосующие — активные при открытии оценки, кроме исключённых автором.** Исключение автором снимает голос в любой момент, и это допустимо: делится не общий ресурс, а **внимание автора** — его личное ребро. Коллеги поправляют мнение автора только в рамках, которые он сам задал допуском людей к запросу и своим распределением. Уход по своей воле во время окна голос не снимает |
| **U50** | **Минимум 5%** у каждого, кто в распределении автора (при 2…20 таких). При 21 и больше — только «поровну» |
| **U51** | ~~Автор не ответил никому → поровну~~ — **поглощено U55**: неотвеченный = «Не могу судить», поэтому молчание автора даёт равный делёж само |
| **U52** | **Названия.** Выплата — «твоя часть в итогах запроса» (не «благодарность»). Исходы — «Выполнено / Не выполнено / Не могу судить» (об оффере, а не о человеке). Закладка — «только для твоей сети» |
| **U53** | **Нейтральный копирайт и никакого давления.** «Пропустить — не отмечаю никого. Твоя часть не меняется никогда» (слово «часть» — только о собственной выплате). Автор **не видит**, кто из помощников уже нажал «Готово»: только то, доступно ли «Завершить сейчас». Фраза о зависимости веса голоса от оценки автора — только в (i) |
| **U54** | **Приглашения.** `closureOpened` помощникам — только при `|M| ≥ 3` (при двоих и одном им нечего делать, кроме закладок, — пишем «можешь поставить 🔖»); ушедшим до оценки — только «можешь поставить ★ (для себя)» |
| **U55** | **«Не могу судить» ≠ «Не выполнено».** «Выполнено» и «Не могу судить» (включая неотвеченное) входят в распределение автора (по умолчанию поровну, минимум 5%); close-ack пишется только за «Выполнено». Вывести человека из распределения автора может только явное «Не выполнено». Так один случайный ответ автора больше не обнуляет всех |
| **U56** | **«Козёл отпущения»: нельзя поддержать всех.** Поддержать всех — то же, что никого. Когда нажата кнопка у последнего отжатого, самая ранняя из нажатых сама отжимается с подсказкой «Поддержать всех — то же, что никого. Кто-то должен отдать: снята самая ранняя (Петя)». Сервер «все поддержаны» принимает как молчание |
| **U57** | **API отдаёт только код полосы** (`raised` / `asIfSilent` / `lowered` / `none`) и исход; числа доли в ответе нет (контракт-тест) |
| **U58** | **Ребро помощник → автор по завершении эпизода.** При финализации каждый член эпохи, который **присутствует в запросе до закрытия** (не ушёл сам и не исключён: `departure` пуст в момент финализации), получает слабое ребро `помощник → автор` (корзина `worked_with_author`). Не зависит от исхода и от распределения автора — иначе автору выгодно ставить «Выполнено». Отменённая эпоха (reopen) ребра не даёт. Защита помощника: кто что-то заподозрил, выходит из запроса до закрытия и ребра не ставит; на явное злоупотребление — бан (перекрывает ребро при публикации). **Суммарный вход автора бюджетирован корнем:** каждый из `n` присутствующих даёт `count = 1/√n`, так что автор за эпизод получает `√n`, а не `n` — большой сбор не делает автора хабом. Сила одного ребра: при `n = 1` ≈ 0.04, при `n = 4` ≈ 0.027; потолок пары 0.08, линейный распад до нуля за 180 дней; в свежее доверие для иммунитета от стены (U39) корзина **не входит**. Экран помощника предупреждает: «Когда запрос закроется, в сети появится слабая связь от тебя к автору: вы работали вместе. Не хочешь её — выйди из запроса до закрытия» |
| **U46** | ~~Независимые ползунки с остатком~~ — **заменено U47**: помощник не видел базы автора, поэтому «5%» могло как поднять, так и опустить человека |

**Снятые решения** (история — §11): U2, U8, U10, U21, U22, U24–U27, U29–U33 — поглощены U34–U38 (rev 10); U35, U46 — заменены U47 (rev 17); U51 — поглощено U55 (rev 18).

### 1.2 Решения этого плана (предлагаются, требуют утверждения)

| # | Решение | Альтернатива |
|---|---|---|
| **P1** | **Доли — на исходящих рёбрах автора; личные рёбра — только из меток.** Доля j — это `author→j` (`helped`): часть, распределённая автором, плюс беспристрастная часть от голосов коллег. | **P8** | **Рассказ** — системное сообщение комнаты (kind 3 `closureStory`), видно всем, кто читает комнату. **Персональный итог** (исход автора по мне, моя часть благодарности, мои собственные метки) — per-viewer запрос плюс receipt в outbox. В комнате нет адресации одному получателю, и новый столбец видимости ради этого не заводится | столбец `recipient_id` у `beacon_room_message` |

| **P10** | После финализации переоткрыть запрос нельзя, как и сейчас (`kMaxReviewReopens = 1`, только из окна оценки) | — |
| **P11** | **Форвардный движок сохраняется** как алгоритм потока 1 (§4.1): DAG → обратное распространение массы с атрибуцией → нормировка по отправителю → бюджет на отправителя. Меняются только вход (одобренные помощники вместо оценок автора) и выход (корзина `routed` на рёбрах `отправитель→получатель`). #### 3.2.1 Назначение корзин и смешивание

Корзина — это **одна причина доверять**, у которой своя память и свой потолок. Корзины не взаимозаменяемы: сколько ни накопи в одной, её вклад ограничен её весом `mix`. Поэтому дешёвый в фарме тип события не может заменить дорогой.

Три ручки на корзину:

- **hl — память.** Каждое событие затухает вдвое за `hl`. Без подкрепления сигнал уходит сам (D5): это единственная санкция за прекращение.
- **k — насыщение.** Вклад корзины равен `s/(k+s)`: при `s = k` корзина даёт половину потолка, дальше отдача убывает. Повторять одно и то же с одной парой почти бесполезно (глубина ограничена).
- **mix — потолок и вес.** Максимальный вклад корзины в ребро. `T = Σ mix·s/(k+s)` лежит в `[0, Σ mix)`.

Абсолютная величина `T` почти не важна: MR нормирует исходящие рёбра каждого субъекта. Важно, как рёбра одного человека соотносятся между собой.

Пример при стартовых параметрах. В эпизоде автор A подтвердил двух помощников, B = 1, ρ = 0.3, так что доля каждого 0.35.
- `helped` у H: `1.0 · 0.35/1.35 ≈ 0.26`.
- Плюс закладка: `0.2 · 1/1.5 ≈ 0.13`. Итого ≈ 0.39 — закладка заметно меньше доли, «немного усиливает».
- Для сравнения, подписка (vouch) = `1.0 · 1/2 = 0.5`.
- Три таких эпизода подряд дают `helped ≈ 0.51`, десять — ≈ 0.78, и никогда не больше 1.0.
- Через год без новых эпизодов `helped` падает примерно вдвое.



```
s_k   = Σ_{live rows of kind k} count · decay_k(age)
        decay_k = 2^(−age/hl_k); max(0, 1 − age/window_k) при linear_window (U58); 1 при hl NULL
T     = Σ_{k: trust} mix_k · s_k / (k_k + s_k)            (vouch: s = 1, если голос > 0)
n     = s_noisy
wall  = 1                    если user_block(subject → object)
      = level(n)             иначе, если T_recent < τ_imm и n ≥ θ (level < 1; U39)
      = 0                    иначе
target = −1        если бан
       = −wall     если wall > 0
       = T         если T > 0
       = 0
```

Смысл: бан сильнее всего; свежее доверие (`T_recent ≥ τ_imm`) сильнее «шумит» (§17.4 записки); стена «шумит» публикуется на незнакомца или на того, с кем нет свежих свидетельств (U39). `T_recent` считается той же свёрткой, но только по строкам журнала не старше 180 дней плюс активный `vouch`, и без корзин с `counts_for_immunity = false` (ребро к автору, U58: работа на автора не должна давать ему иммунитет от стены за спам бывшим помощникам).

#### 3.2.2 Иммунитет: сколько держит один сигнал (стартовые параметры)

| Один сигнал | Вклад в `T_recent` сразу | Держит иммунитет (`≥ 0.05`) |
|---|---|---|
| активная подписка `vouch` | 0.50 | пока подписка активна (состояние, не свидетельство: у него нет возраста) |
| доля `helped` 0.23 (трое равных) | 0.19 | все 180 дней |
| закладка `marked` | 0.13 | все 180 дней |
| `useful_forward` 1 | 0.17 | все 180 дней |
| `engaged` 1 | 0.07 | ≈ 53 дня (затухание 90 д) |
| `routed` 0.1 | 0.045 | не даёт |
| `worked_with_author`, `n = 1` (U58) | 0.04 | не даёт (корзина не входит в `T_recent`) |

Почему `vouch` оставлен в иммунитете, хотя решение звучит «только последние 180 дней»: подписка — текущее состояние, а не событие с возрастом. Если бы стена могла перекрыть активную подписку, при публикации одним скаляром (§17.4 записки) подписка A на B исчезла бы из MR целиком — частное раздражение получило бы публичное следствие в чужих рамках. Решение владельца (rev 15): `vouch` в иммунитете **оставлен**.

Коэффициенты — стартовые; их подбирают на живой базе или агентной модели. В фазе A есть только ветки «бан → 0» (как сейчас) и T. Ветка стены и «бан → −1» включаются в фазе B.

**Правило публикации:** публикуем, если `|target − prev| > ε` **или** сменился знак **или** сменился квантованный уровень стены.

pool_h = (1−ρ)·B,  pool_r = ρ·B

# часть коллег: срез i = (1−α)·pool_h·[β/n + (1−β)·a[i]/100]   (U45)
для i ∈ M:
  O = M ∖ {i}
  если Σ_{k∈O} a[k] > 0: base(j) = a[j] / Σ_{k∈O} a[k]  для j ∈ O   # «как решил автор» среди других
  иначе:                 base не определена

imp[j]   = Σ_{i ≠ j} slice_i·dir_i(j)

для j с final[j] > 0:  author→j  helped  final[j]            key closure:<b>:<e>:helped:<j>

| Свойство | Утверждение |
|---|---|
| Доля сдвига рамки (U23) | В рамке автора `Σ helped + Σ marked(автор→·) + Σ routed(автор→·)` ограничена `B + |M|`; в рамке помощника — только закладки, не больше `|M|` штук по 1; в рамке отправителя `Σ routed(sender→·) ≤ ρ·B`; `|M| = 2` и `|M| = 20` дают один потолок `helped` |
| Беспристрастность | Изменение отметок, «Готово» или закладок помощника i при прочих равных **никогда** не меняет `final[i]` (перебор на случайных входах, фиксированный seed) |
| Голос не ставит рёбер | Любые отметки при пустых `S` → ни одной строки между помощниками |
| Сохранение пула | `Σ final ≤ pool_h`; равенство, пока у каждого промолчавшего есть кому уйти по распределению автора. Срез не чеканится только у промолчавшего, которому автор дал всю свою часть |
| Молчание следует автору | Никто не голосовал и автор распределил поровну по всем → `final` = равный делёж; при неравном распределении автора порядок долей сохраняется |
| Монотонность (U47) | Поддержка j никогда не даёт j меньше, чем молчание голосующего; отжатый никогда не получает от него больше |
| Поддержка работает | Поддержка при хотя бы одном отжатом с базой > 0 даёт поддержанному **строго больше**, чем молчание |
| Все поддержаны (U56) | «Поддержать всех» = молчание (масса не теряется); интерфейс такой голос не собирает |
| Отжатые | При поддержке кого-то отжатые получают от голосующего меньше базы — они её финансируют; это сказано на экране индикатором ▼ |
| Нет автоматических рёбер | Ребро между помощниками появляется только из закладки, в направлении отмечающий → отмеченный |
| «Не могу судить» (U55) | `nb` и неотвеченное входят в `A` (равная доля по умолчанию), close-ack нет; вне `A` только «Не выполнено» |
| Все «Не выполнено» | Только закладки и routed (I4) |
| Вес голоса (U45) | `Σ_i slice_i = (1−α)·pool_h`; при `β = 0.5` у того, кто вне `A`, — половина равного среза |
| Голосующие (U49) | Исключённый автором (в любой момент) не голосует; ушедший по своей воле во время окна голосует; ушедший до окна не голосует |
| Минимум 5% (U50) | При `2 ≤ |A| ≤ 20` у каждого в `A` `a ≥ 5`; при `|A| > 20` — поровну |
| Вне распределения автора | j ∉ A получает только `imp[j]` из голосов других; коллеги могут его поднять (U42) |
| Ушедший | Член M с `departure`; получает часть автора и голоса других, может получать и ставить закладки; не голосует, если ушёл до окна или исключён; ушедший добровольно не входит в `M_route`, исключённый автором — входит |
| «Готово» (U44) | Учитывается последняя учтённая версия; черновик после неё её не отменяет; без «Готово» = молчание |
| Полоса (U48) | Молчание всех → у всех `asIfSilent`; одна пара ↑ друг другу при трёх равных — ниже порога; `none` при `|M| ≤ 2` и при нулевой части |
| Порядок строк | Перестановка членов не меняет итоги |
| Один раунд | Никакая запись после финализации не меняет `final`; закладки — только свои и только они (U37, U40) |
| Двое | При `|M| = 2` голосов нет; `final` = распределение автора (`α = 1`) |
| Один помощник | При `|M| = 1`: `final` = `pool_h`, если он в `A` |
| Паддинг цепочки | Вставка лишних звеньев не увеличивает массу ни в одной честной рамке: каждый отправитель ограничен своим бюджетом |
| Детерминизм | Одинаковый вход → одинаковые `source_key` и суммы |

### 4.2 Делёж: автор и коллеги (U34–U36)

**Что делится.** Делится не общий ресурс, а **внимание автора** — его личное ребро к помощникам. Поэтому автор вправе задать рамки: кого допустить к запросу, кого исключить (исключённые не голосуют, U49) и как распределить свою половину. Коллеги поправляют мнение автора только внутри этих рамок.

**Почему автор участвует.** Автор — главный свидетель эпизода: он видел все офферы и их результат. Сам себе он долю не назначает, но его мнение получает особый вес: `α_A = 50%` пула помощников он распределяет сам. Остальные 50% делят коллеги беспристрастно. Так у автора есть голос, пропорциональный его роли, а у коллег — возможность не согласиться с ним своей половиной. Это возможность, а не гарантия: промолчавшие отдают свой срез распределению автора, при пустом C коллеги ничего не создают, а при двух помощниках делёж целиком авторский.

**Часть коллег.** Каждый помощник сдвигает свой срез `(1−α)·pool_h·[β/n + (1−β)·a_i/100]` между **другими** кнопкой «Поддержать» (U47): по умолчанию срез идёт так, как решил автор, а поддержка сдвигает его к поддержанным за счёт остальных. Доля j зависит от решения автора и голосов других, но не от голоса самого j. Это простейший беспристрастный делёж (partition rule, в духе de Clippel–Moulin–Tideman 2008). Консенсусное свойство точной формулы dCMT он не даёт. Спасибо после дележа больше нет, поэтому беспристрастна **итоговая** доля: собственный голос не меняет собственный итог. Устойчивости к коалициям это не даёт — сговор пар возможен и принят (U43).

**Вес голоса (U45).** Половина веса голоса у всех равная, половина — пропорциональна доле, которую назначил автор. Это первый шаг транзитивности «доверие автора → вес голоса» без потери беспристрастности: вес зависит только от решения автора, а не от своего голоса. Кольца непризнанных автором теряют половину силы; те, кого автор вывел «Не выполнено», сохраняют половину голоса. Сговор пар, признанных одинаково, не меняется (U43).

Полная транзитивность (личный PageRank автора на мини-графе запроса) с нормировкой ломает беспристрастность: голос за союзника вместо молчания уводит блуждания от третьего и поднимает собственную долю (36,9 → 41,9 в прогоне). Беспристрастный вариант leave-one-out требует плавающего бюджета и не объясним на схеме — вынесен в исследование (§12).

**Молчание = как решил автор.** Срез того, кто не отметил никого, нажал «Пропустить» или не нажал «Готово» (U44), делится так, как распределил автор, но только между остальными (себе нельзя — иначе молчание меняло бы собственную долю). Копирайт: «Пропустить — не отмечаю никого. Твоя часть не меняется никогда» (U53).

**Почему одна кнопка, а не проценты (U47).** Помощник не видит распределения автора (P4). Любое число в ползунке — это число относительно невидимой базы: при авторских 70/20/10 «Оле 5%» опускало её с 15,3% до 8%, а при 10/20/70 «Оле 50%» тоже опускало её. Поддержка монотонна: не опускает поддержанного относительно молчания, и базу знать не нужно.

**Почему одна кнопка без «=» и «↓» (rev 18–19).** При сохранении пула из трёх свойств совместимы только два: «неотмеченный не теряет», «„=“ не теряет», «одна поддержка работает без „↓“». С «=» добросовестный голос «↑ одному, = остальным» ничего не сдвигал, а «не видел» при чужом ↑ платил как ↓. Выбрано: поддержка работает, и платят отжатые — это видно по индикатору ▼. Альтернатива «↑ берёт только у ↓» честна, но почти не работает: ↓ воспринимается как донос. Отдельная «↓» при одной кнопке не нужна: опускание происходит только как цена чужой поддержки. Прогон (`α = β = t = 0.5`, трое, доли от пула помощников):

| Сценарий | Итог Маша / Петя / Оля |
|---|---|
| Автор 70/20/10, все молчат | 55,1 / 29,6 / 15,3 |
| … Маша поддержала Олю | 55,1 / 21,0 / **23,9** |
| Автор 10/20/70, все молчат | 15,3 / 29,6 / 55,1 |
| … Маша поддержала Олю | 15,3 / 28,4 / **56,3** |
| Автор поровну, Маша поддержала Петю, Петя — Машу | 37,5 / 37,5 / 25,0 |
| Автор 50/50/0, двое поддержали Олю («Не выполнено») | 39,6 / 39,6 / **20,8** |
| Все поддержали всех (интерфейс не даёт собрать) | 33,3 / 33,3 / 33,3 (= молчание) |
| Автор: Маша «Выполнено», остальные «Не могу судить» | 33,3 / 33,3 / 33,3 |
| Автор: Маша «Выполнено», остальные «Не выполнено», все молчат | 66,7 / 0 / 0 (срез Маши не чеканится — ей автор дал всё) |

Сговор пары при кнопке слабее, чем при ползунках (37,5 против 41,7): партнёр забирает только долю `t` у остальных.

**Знать решение автора не нужно (rev 22).** Помощник не видит распределения автора, поэтому вопрос «кого автор недооценил» для него — догадка. Правило делает эту поправку само: добавка поддержанному `j` от среза `i` равна `slice_i·t·Σ_{k∈N} base(k)/|U_i|`, то есть тем больше, чем меньше у `j` доля автора среди других коллег `i`; отжатый `k` отдаёт `slice_i·t·base(k)` — пропорционально тому, что ему дал автор. Кого автор уже «утопил», почти ничего не теряет, кого оценил высоко — получает от поддержки мало. Прогон: трое, автор дал Маше 30, Маша поддержала Олю, остальные молчат (доли от пула помощников):

| Автор Маша / Петя / Оля | Оля: молчание → поддержка | Петя: молчание → после |
|---|---|---|
| 30 / 70 / 0 (Оля «Не выполнено») | 0 → 7,9 (**+7,9**) | 56,7 → 48,8 |
| 30 / 50 / 20 | 22,9 → 28,5 (+5,7) | 44,6 → 39,0 |
| 30 / 35 / 35 | 34,6 → 38,6 (+4,0) | 34,6 → 30,7 |
| 30 / 10 / 60 | 50,8 → 51,9 (+1,1) | 13,1 → 12,0 |
| 30 / 0 / 70 (Петя «Не выполнено») | 56,7 → 56,7 (0) | 0 → 0 |

Поэтому вопрос помощнику — о том, что он сам знает: «чья работа, по-твоему, была важной». Социально-психологические риски, которые остаются: **заметность и ореол** (помощники и автор замечают одного и того же громкого участника, поддержка слегка усиливает неравенство — гасится убывающей добавкой); **поддержка тихого «на всякий случай»** (выгодна ему ровно тогда, когда автор его недооценил); **угодничества перед автором нет** — автор голосов не видит (U36), своя часть от голоса не зависит; **ощущение бесполезного голоса** — помощник не узнаёт эффекта своей поддержки, участие может сойти к молчанию (метрика в §8); сговор пар — U43.

**Малые группы.**

| `|M|` | Автор | Коллеги |
|---|---|---|
| 1 | весь пул одному, если подтверждён | — |
| **2** | распределяет **100%** слайдером соотношения (U28) | делёж для двоих вырождается — голосов нет; остаются метки |
| ≥ 3 | распределяет `α_A = 50%` по «Выполнено» и «Не могу судить» | сдвигают `50%` кнопкой «Поддержать» |

**Роль автора.**
- Решает исходы (кто в `A`, кому close-ack) и распределяет свою часть; исключает людей — и тем снимает их голос (U49).
- Задаёт, куда идут срезы промолчавших.
- Не видит голосов, итогов помощников и чужих меток и не утверждает их (D11).
- Если автор отметил «Не выполнено» всем, `helped` не чеканится (U14); закладки записываются всё равно.
- Направить срез тому, кого автор отметил «Не выполнено», — право коллег: так они могут частично не согласиться с автором.

**Видимость (U36, U48).** Помощник видит только свой итог — словами относительно молчания коллег — и исход автора по себе. Полное распределение, чьи-то голоса и проценты «кто кому» приложение не показывает никому. Это защита показа, а не невыводимость: при двух помощниках свой итог однозначно даёт чужой, а сверка чисел оффлайн сужает возможные голоса. (Уравнений по итогам не хватает для точного восстановления голосов в общем случае — одно из них зависимо, — но вместе со знанием своего голоса и распределения автора картина восстанавливается сильно.)

### 4.3 Закладка 🔖 (U37)

- **Смысл:** «в этом эпизоде я испытал к этому человеку благодарность — пусть моё ребро к нему в сети немного усилится». Это не поручительство и не рекомендация, а небольшая поправка своего отношения.
- Одно касание по закладке у человека на экране дележа. Снять — так же. До финализации это черновик; применять не нужно.
- Кого можно отметить: помощнику — других помощников и автора; автору — помощников. Отметка автора закрывает пробел из записки §20.2.
- При финализации каждая метка — строка `marked` (count 1) в рамке отмечающего. Затухание 365 д, насыщение `k = 0.5`, потолок `mix = 0.2`: одна звезда даёт ≈ 0.13 — меньше типичной доли `helped`.
- **После закрытия** (U37): в карточке «Итоги для тебя» закрытого запроса закладки у всех участников эпизода (помощников и автора) можно ставить и снимать. Это запись или отзыв строки (`retracted_at`, P7) и пересборка пары. Дата строки для затухания — всегда **дата закрытия запроса**: звезда, поставленная через год, уже затухла на год; снять и поставить заново — не способ её «освежить».
- **Никому не показывается**, включая цель. Отмечающий видит свои закладки в своём итоге эпизода.
- **Бесплатность.** Ритуал держится на показе, а здесь показа нет. Договор «отметим друг друга» проверяем только тем, что люди показывают друг другу свои экраны, — это принято. Рамка отмечающего нормируется MR: лишние закладки размывают его собственные рёбра. Звёзд за эпизод — не больше `|M|`.
- Взаимные и круговые метки разрешены; их анализ — отдельный уровень над журналом (§12). Отдельных метаданных не пишем (U43).

### 4.1 Поток 1: обратное распространение по цепочке (движок сохраняется)

Что делает движок сейчас:
- Для каждого коммиттера строит DAG форвардов, созданных до его оффера и не отменённых, с корнем у автора.
- Пускает массу 1.0 назад от коммиттера. У самого коммиттера она делится поровну между теми, кто ему переслал. Выше по цепочке — по весам `forward_decision_attribution` («я переслал, потому что получил от X»), иначе поровну.
- Нормирует массу внутри каждого отправителя и складывает по коммиттерам.
- Выдаёт каждому отправителю бюджет 1.0 на запрос, распределённый по его получателям пропорционально их вкладу.
- Пишет свидетельство на ребро **отправитель → получатель**: «моё решение переслать сюда сработало».

Что меняется:

| | Сейчас | Становится |
|---|---|---|
| Кто запускает массу | коммиттеры, которых автор оценил; значение оценки → bin | **`M_route`** — все члены эпохи, кроме ушедших добровольно (U41), с массой 1.0 каждый; исход не важен (U15, I4) |
| Бюджет на отправителя | 1.0 за запрос | **ρ·B** за эпизод (параметр) |
| Выход | bins good/veryGood/noEffect в контексте forward ×0.2 | корзина `routed`, count = доля бюджета |
| Неудачные форварды | `unsuccessfulRequestForward` (noEffect) | **удаляется** — неудача = отсутствие платежа (записка §16) |
| `negativeRoute` | noEffect-провенанс для оценок 1–2 | **удаляется** — знаковой шкалы больше нет |
| Идемпотентность | `hasForwardEvidenceForRequest` | `source_key` с эпохой + отзыв эпохи при reopen |

Почему бюджет на отправителя, а не фиксированная сумма на эпизод (как в записке §11). Паддинг цепочки сибилами создаёт массу только на рёбрах самих сибилов. Масса в честной рамке — например, `F→S1` у честного форвардера F — ограничена бюджетом F. Прибыль кольца ограничена attack edges, как и должно быть. Фиксированная сумма на эпизод ограничивала бы то же самое, но ценой того, что длинная честная цепочка платит каждому звену меньше.

Сочетание с корзинами. Поток 1 — это просто ещё один писатель корзины `routed`. Повторные успешные маршруты `F→R` в разных эпизодах накапливаются и насыщаются (k = 1): это и есть «F знает, куда слать». Затухание 182 д. Тот же `F→R` может одновременно нести `vouch`, если F подписан на R: корзины складываются через свёртку, каждая со своим потолком. Потоки 1 и 2 направлены противоположно и не дублируются. Поток 1 — `F→H`: «правильно, что я переслал H». Поток 2 — `H→F`: «F прислал мне стоящее».

Переименование: `ForwardOutcomeFinalizer` → `ForwardRoutingSettlement`. `forward_outcome_policy.dart` удаляется. `TrustBin`/`TrustSourceType` в движке заменяются на `TrustEvidenceKind.routed`. Юнит-тесты движка (`forward_outcome_finalizer_test`, `forward_request_consolidator_test`) переносятся с новым входом; удаляются только ветки negativeRoute и unsuccessful.

## 5. Жизненный цикл закрытия

```
open family ──close──▶ reviewOpen (epoch e, status 0)
   │                     │  автор: outcomes / распределение / метки / story (черновики)
   │ (если коммиттеров   │  помощники: «Поддержать», закладки, «Готово»
   │  никогда не было)   ├──reopen──▶ open family   (epoch e → 2 cancelled; черновики живут)
   ▼                     ├──closeNow (P3)──┐
 closed                  └──closes_at < now (sweep)──┴──▶ finalize ──▶ closed (epoch e → 1)
```

**finalize** — одна транзакция под локом запроса:

1. Статус эпохи становится 1, `beacon.status = closed`, событие жизненного цикла.
2. Собрать вход, вызвать `EpisodeSettlement`.
3. Записать свидетельства в журнал (`ON CONFLICT (source_key) DO NOTHING`), затем пересобрать затронутые пары.
4. Записать close-ack capability-события (P5), в той же транзакции (help-tag §764).
5. Если рассказ непуст — системное сообщение комнаты `closureStory` (kind 3).
6. Outbox, по получателю: исход автора по нему и его итог словами (U48) — каждому члену; тем, у кого остался неучтённый черновик, — «твой черновик не был учтён» (U44). Закладки не порождают уведомлений.
7. Закрыть обязательства (supersede) — как сейчас.

**reopen**: эпоха получает status 2. Свидетельства эпохи отзываются (`retracted_at`), пары пересобираются. В фазе A это пустая операция, потому что до финализации свидетельств нет, но функция пишется общая. Статус возвращается в open, `review_reopen_count++`, отправляется receipt `closureCancelled`. Черновики не трогаются; учтённые версии отметок (`version = 1`) понижаются до черновиков — после reopen их нужно подтвердить «Готово» заново (U12).

**Вход в эпоху (close):** снимок `beacon_closure_member` = все когда-либо одобренные (`everAcknowledged`, с учётом 24 ч grace) с `departure` по последнему событию обязательства, `voter` = активен в этот момент (U49), плюс `arrival_edge_id`. Уход **во время** окна проставляет `departure`, но `voter` не меняет. Receipt `closureOpened` (U54): автору — «подведи итоги»; голосующим помощникам при `|M| ≥ 3` — «можешь отметить коллег (необязательно)»; остальным — «можешь поставить 🔖 (для себя)». За 24 ч до закрытия — напоминание голосующим с неучтёнными изменениями.

- Как часто открывают схему (i).
- **Эффективность голоса (rev 22):** доля голосующих, нажавших «Готово» хотя бы с одной поддержкой, по порядковому номеру эпизода у одного человека (1-й, 2-й, 3-й … эпизод с `|M| ≥ 3`). Падение с номером — признак «мой голос ничего не решает»; тогда половина коллег фактически сходит к решению автора.
- Совпадение поддержки с решением автора: доля поддержек, отданных члену с наибольшей долей автора среди других, — признак ореола и заметности.
- Сообщения в комнате с процентами или «спасибо» после закрытия.
- Повторное участие по полосе итога U48 — признак обиды.
- Пилот: сравнить `α_A = 0.5` и `α_A = 1` и `β = 1` против `β = 0.5` — **только на эпизодах с `|M| ≥ 3`** — по признанию незаметной работы, воспринимаемой справедливости и повторному участию.

**Тест понимания (пилот, до запуска)**
- Формат: итеративно (RITE) — 2–3 раунда по 8–10 человек с правками между раундами, затем подтверждающий раунд по 20 на роль (автор / помощник); не меньше половины — новички; мобильный как основной, плюс проверка на десктопе (клавиатура, hover). QA-стенд с засеянными эпизодами: 3 помощника, 2 помощника, с ушедшим, с «Не выполнено», с «Не могу судить». Инженерные панели симулятора участникам не показывать. Сначала самостоятельный проход без подсказок, потом разбор вслух и (i). Через сутки — вопросы 2, 3б и 10 в другой формулировке. Отчёт — абсолютные числа и причины ошибок, а не один процент.
- Задачи. Автор: закрыть поровну; «Маша сделала больше всех — отрази это»; «Пете не могу судить»; убедиться, что ответы учтены. Помощник: «Иван заслужил больше — сделай это»; «не хочу участвовать»; поставить закладку; «передумал — поменяй» (после «Готово»); попытаться поддержать всех.
- Вопросы с правильным ответом:
  1. а) Ты поддержал только Ивана. Он получит больше, меньше или столько же, чем если бы ты промолчал? (Больше.) б) Что при этом получат те, кого ты не выбрал? (Немного меньше — что значит ▼.)
  2. Узнает ли Петя о твоей закладке? Придёт ли ему уведомление? Увидят ли её люди из твоей сети? (Нет, нет, нет.)
  3. а) Ты выбрал отметки и вышел, не нажав «Готово». Учтётся? (Нет.) б) Ты нажал «Готово», потом поменял и вышел. Что в расчёте? (Прошлая версия.)
  4. Кто увидит твой выбор? (В приложении — никто; по своим итогам могут догадаться.)
  5. Карточка «Твоя часть — как если бы коллеги промолчали» при неравном распределении автора: коллеги изменили твою часть? (Нет.) И: у тебя «коллеги опустили» — кто это сделал? (Коллеги в целом; кто именно — не узнать.)
  6. Автору: ты поставил 80/10/10, коллеги молчат. Маша получит 80%? (Меньше.)
  7. Можно ли что-то изменить после закрытия? (Только свои закладки.)
  8. Двое: узнает ли Петя точное число Маши? (Нет.) Поймёт ли, как автор разделил? (Примерно да.)
  9. Что будет, если нажать «Пропустить»? (Никого не отмечаешь; между коллегами — как решил автор; твоя часть не меняется.)
  10. Может ли твоя поддержка изменить твою собственную часть? (Нет.)
  11. Автору: чем «Не могу судить» отличается от «Не выполнено» для доли человека? (Первое оставляет в равной доле, второе убирает.)
  12. Нужно ли знать, как распределил автор, чтобы решить, кого поддержать? (Нет: отмечаешь важную, по-твоему, работу; если автор уже оценил человека высоко, добавка маленькая.)
- Критерии: вопросы 2, 3, 4, 9, 10 — не меньше 85% верных и ни одного уверенного «закладка уведомляет»; 1, 6, 11, 12 — не меньше 85%; задача «Иван заслужил больше» — итог Ивана **строго выше** молчания в 90% попыток ; задача «поддержать всех» — участник понял подсказку U56 (пересказ); вопрос 5 — без шкалы −2…+2, чувство обиды не считается ошибкой, фиксируется отдельно; пересказ механики после (i) по рубрике: половина автора; молчание → автор; поддержка берётся у отжатых; своя часть от отметок не зависит; закладка приватна — ошибка по любому пункту считается ошибкой; медиана задачи помощника ≤ 90 с; SEQ ≥ 5/7.
- Социальные нормы стенд не покажет: отдельный групповой этап на реальных эпизодах (повторные группы) и интервью после 30 закрытий с участниками, у которых была полоса «коллеги опустили».

Исследование (агентная модель): беспристрастный leave-one-out личный PageRank автора на мини-графе запроса (доля j считается на графе без исходящих рёбер j, нормировка на константу при всеобщем молчании) против дележа с `β` — по совпадению долей с истинным вкладом и по устойчивости к кольцам (U45).

Уровень обработки взаимности и циклов над свидетельствами `marked` (U37) и долгосрочный анализ сговора пар (U43).

Идея на будущее (не решено, есть последствия): «восстановление справедливости» относительно мнения автора должно чего-то стоить — например, сдвиг против распределения автора сжигает часть веса голосующего.

Отложено решением U17: утечки на стороне чтения (`graph()` / `graph_edges_between` / `user_trust_edge_degree` с `positive_only=false`, оракулы, суточное квантование публикации).
