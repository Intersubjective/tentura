# Срок жизни поста (≤ 3 дня) и архив — дизайн

**Статус:** shipped (client/server 7.50.0); rev 1.1 (2026-10-23), решения владельца приняты (§2, D1–D10). Не план имплементации.

## 1. Суть

Пост живёт как сториз: **не дольше 72 часов от публикации**. Автор может срок сократить (вплоть до
«Завершить сейчас»), продлить — нельзя. По истечении пост закрывается и уходит в **архив** в
состоянии read-only. Ценный разговор продолжается в отпочкованном Запросе — отпочкование
становится естественным выходом из поста, а не опцией.

Что меняется относительно сегодняшнего:

| Сейчас | Станет |
|---|---|
| `PostsCubit.quietAfter = 72h` от `lastActivityAt`, окно **скользит** с каждым сообщением | жёсткий `expires_at` от публикации, не скользит |
| только клиентская визуалка («Затихли», уход с поля); писать можно всегда | сервер отказывает в записи после `expires_at` |
| закрыть пост (status 6) можно только отпочкованием | ещё: истечение срока и «Завершить сейчас» автора |

## 2. Решения владельца (2026-10-23)

| # | Вопрос | Решение |
|---|---|---|
| D1 | Отпочкование из архивного поста | **Разрешено** участникам поста, как из открытого. Пост не переоткрывается; в него пишется только системная карточка «оформил(а) запрос …». |
| D2 | Обход запрета продления копией поста | **Не боремся.** Новый пост — честное действие: заново видят, заново работают шумовые механизмы. |
| D3 | Поздняя пересылка | **Показывать остаток времени** в интерфейсе (карточка, шапка, диалог пересылки). Запрета пересылки по остатку нет. |
| D4 | Закреплённый пост | Пин держит пост наверху списка, но **срок не продлевает**: после истечения он там же, read-only. |
| D5 | Предупреждение | Автору — уведомление «Пост закроется через 3 ч» с действием «Оформить запрос»; кнопки продления нет. Участникам — без пушей. |
| D6 | Срок хранения архива | **Вечно** (пока). Вернуться при вопросе о хранении вложений. |
| D7 | Существующие посты | Льготный период: `expires_at = max(published_at + 72h, now() + 24h)` на момент миграции — нужны живые посты для тестов. |

Подтверждено владельцем 2026-10-23:

| # | Вопрос | Решение |
|---|---|---|
| D8 | Начало отсчёта | Момент публикации; черновики не истекают. |
| D9 | Выбор срока | При публикации: 6 ч / 24 ч / 3 дня (по умолчанию 3 дня). После публикации — только сокращение, включая «Завершить сейчас» (ручного закрытия сейчас нет). |
| D10 | Причина закрытия | Статус тот же (6, closed); причина в журнале переходов: `expired` / `closedByAuthor` / `budded`. Интерфейс: «Истёк» / «Автор завершил» / «Вырос в запрос …». |

## 3. Что значит read-only

| Действие в архивном посте | |
|---|---|
| Новые сообщения, реакции, голоса в опросах, эстафеты (Baton) | ❌ — итоги опросов окончательные |
| Пересылка, приглашения (в т.ч. автором) | ❌ |
| Удалить своё сообщение / автору удалить пост | ✅ право на удаление важнее read-only |
| «Не интересно» / «Вернуть», личный пин | ✅ личное состояние, не контент |
| Отпочковать Запрос | ✅ (D1) |

Сегодняшние «Затихли» в «Разговорах» превращаются в **«Архив»**. Поле: истёкший незакреплённый пост
отсутствует, закреплённый — dormant (как уже описано в G2b). «Для вас»: строка поста уходит при
закрытии.

## 4. Технические контуры (для архитектуры)

1. **Данные.** Новая колонка `beacon.expires_at timestamptz`: `NOT NULL` для открытого поста
   (kind = 1, status = open), `NULL` для Запросов; CHECK `expires_at <= published_at + interval '72 hours'`.
   `end_at` не переиспользуем: у Запросов это событие/дедлайн, а `beacon_post_shape_ck` для поста
   его запрещает. Нужен надёжный `published_at` поста — проверить, есть ли он, иначе ввести.
2. **Сокращение.** Мутация принимает только `new_expires_at < expires_at`; `<= now()` = закрыть
   сейчас (`closedByAuthor`).
3. **Истина — время сервера.** Все пути записи в пост (сообщения, реакции, опросы, Baton,
   пересылка, приглашения, принятие приглашений) проверяют `status = open AND now() < expires_at`.
   Гонка на последней секунде решается сервером.
4. **Sweeper** материализует статус: периодически переводит истёкшие посты в 6 с причиной
   `expired`, чтобы обновились списки, «Для вас», поле и realtime. Берёт блокировки в порядке §0
   (иерархия → пост → …), иначе вернутся дедлоки уровня отпочкования. Окно между `expires_at` и
   проходом sweeper'а безопасно благодаря п. 3.
5. **Отпочкование из архива (D1).** `PostCloseOperation.closeForBud` сейчас бросает
   `PostNotOpenException` для не-open поста; для уже закрытого поста — пропускать закрытие и
   писать только системную карточку. Проверка «участник поста» остаётся.
6. **Предупреждение (D5).** Тот же sweeper (или отдельный проход) ставит уведомление автору за 3 ч;
   идемпотентно, один раз на пост; не слать, если до истечения при публикации < 3 ч.
7. **Клиент.** Убрать скользящий `quietAfter`; «Сейчас» / «Архив» по статусу и `expires_at`;
   остаток срока (кольцо ◐ из mockups + текст «осталось 5 ч») в карточке, шапке и диалоге
   пересылки; composer — выбор срока; ⋯ автора — «Сократить срок» / «Завершить сейчас»;
   read-only композер с причиной закрытия и кнопкой «Оформить запрос».
8. **Выкатка.** Одна раздача, legacy-клиентов нет: поднять `kDefaultMinClientVersion`. Миграция
   заполняет `expires_at` по D7.
