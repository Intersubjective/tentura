# Шум в контактах — журнал обсуждения

**Назначение:** хронология дизайн-обсуждения санкций за шум (noisy contact). Журнал ведётся так, чтобы обсуждение можно было продолжить в другой сессии или с другой моделью без потери контекста. Итоговые формулировки живут в [`noisy-contact-sanctions-design.md`](noisy-contact-sanctions-design.md). Здесь — путь к ним: что спрашивали, что нашли, что отвергли и почему.

## Как продолжить (для следующей модели)

1. Прочитай диздок целиком, затем этот журнал с конца: последние записи важнее.
2. **Симулятор:** `docs/plans/noisy-contact-sanctions-simulator.html` — открыть в браузере, без сборки.
   - Опубликованная копия: https://claude.ai/artifact/7oR3Wka7wGdpnfhJeetGB1 (приватная, доступ у владельца).
   - Рабочий исходник в прошлой сессии лежал в scratchpad. Источник правды теперь — файл в репо.
   - Правки: одна страница, чистый HTML+JS, без npm и бандлеров. Тема следует только ОС.
   - Модели в коде: `fold`/`project` (cur, prop), `stagesState` (stages), `simulate` (расписание проекций и шлюз публикации), `mr` (точное матожидание цепочки).
3. **Код, на который опирается обсуждение:**
   - `packages/server/lib/data/database/migration/m0202.dart` — ledger, `trust_fold_pair`, kind config;
   - `m0206.dart` — noisy, вид 7;
   - `m0207.dart` — текущий `trust_project_pair`;
   - `packages/server/lib/domain/use_case/contact_resolution_sweep_case.dart`, `trust_maintenance_case.dart`;
   - `packages/server/lib/data/repository/trust_publish_repository.dart`;
   - спека стен MR: `~/MY_SRC/meritrank-rust/NEGATIVE_EDGES_FEATURE.md`.
4. **Ограничения владельца:**
   - обсуждение на русском;
   - prod не трогать, dev — `root@dev.tentura.io`;
   - не коммитить без просьбы;
   - любой `dart test` / `flutter test` оборачивать в `scripts/run_with_test_cleanup.sh`;
   - фронтенд — без npm;
   - **журнал и диздок обновлять по ходу обсуждения, регулярно**;
   - при содержательной смене дизайна поднимать rev диздока и добавлять запись в §11.
5. **Стиль обсуждения, который владелец ждёт:** разбор с позиций социального дизайна, социальной психологии, нейронауки (аналогия люди = нейроны) и «наших пяти авторов» (Ostrom, Bourdieu, Boltanski/Thévenot, White, Levin; Deleuze/Guattari — только как модель угроз, см. social-design §5). Плюс здравый смысл и честная критика, включая самокритику предыдущих предложений.

### 2026-10-03 — предложение владельца (G1–G6) и критика

- **Предложение владельца** (дословно сжато в диздоке §1; ключевые фразы):
  - «если Y начинает спамить X чем-то, что X находит неважным, Y постепенно теряет долговременное доверие, но при этом также подвергается кратковременной стене "шумит"»;
  - «"не интересно" определяется только по запросам-постам-пересылкам которые цель пересылки реально просмотрела потратив на это время»;
  - «нотификацию Васе что он конкретному человеку без толку шлет ... если отправка продолжается ... санкции против Васи усиливаются ... перманентное снижение веса ребра в MR вплоть до негативного имеет смысл, потому что оно защищает окружение цели Васи».
- **Критика:**
  - сильные стороны и риски — диздок §7, §8;
  - главная поправка про MR: минус X не защищает окружение X (R6), защищает снятие положительного T;
  - уведомление делает долговременную санкцию легитимной по инварианту, потому что она становится видимой.
- **Результат:** кандидат D (стадии 0–2) в диздоке §7.
