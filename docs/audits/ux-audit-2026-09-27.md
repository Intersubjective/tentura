# UI/UX audit — 22 main screens, compact + expanded (2026-09-27)

A screenshot sweep of the Flutter web client at two widths, followed by a
screen-by-screen UI/UX review, a consolidated defect list and a phased fix
plan. Related earlier audits: [`responsive-design-audit.md`](responsive-design-audit.md),
[`desktop-adaptive-readiness-report.md`](desktop-adaptive-readiness-report.md),
[`beacon-detail-qa-audit.md`](beacon-detail-qa-audit.md).

  Caveat: the dev server was started at 23:13, and `7edde2ff8` (card keylines,
  23:47) may not have been hot-reloaded. Re-check the My Work card findings

  `elena-ux@test.tentura.local` was added so she can use QA test-login.
- **Script:** `reports/ux-audit-2026-09-27/shots.js` (gitignored, next to the
  PNGs). It uses Playwright-core with system Chrome. It cold-boots once per
  viewport and then navigates by hash, waiting 4 s per screen (6 s for maps).
  It re-runs with `node shots.js <outdir> [screen-regex]`.
- **Viewports:** `mobile` 390×844 and `desktop` 1440×900, both at DPR 1.
- **Console:** no Flutter errors, RenderFlex overflows or page errors on any
  of the 46 captures (`console.json`).
- **Review:** four parallel reviewers, each covering 5–7 screens across both
  viewports. The lead spot-checked the P1s against the PNGs. S13-1 was
  corrected: `tab=room` is a legacy key (the normalizer only accepts
  `tab=threads`), so it is a silent fallback rather than a broken Chat tab.

Severity: **P0** blocker · **P1** major (wrong info, broken hierarchy, a11y
fail) · **P2** minor · **P3** polish. Viewport: **M** compact, **D** expanded.

## Fix plan

Order: shared components first (one fix clears many screens), then
per-screen IA, then polish. Every unit goes through the `material-3-flutter`
skill: tokens only, no raw constants in `features/**/ui` or `ui/**`, and
`scripts/check-custom-lints.sh` must stay at baseline. Each unit is verified
by re-running `shots.js` on its screens at both viewports, plus widget or
golden tests where the component has them. Wrap test runs in
`scripts/run_with_test_cleanup.sh` and run them serially.

### Phase 1 — shared design-system components (clears X-02, X-04, X-05, X-08, X-14)

1. **`TenturaEmptyState`** (icon + title + one-line body + optional CTA).
   Adopt it on 03, 04, the short-list footer on 06, and the closed/empty
   states on 12–14. Acceptance: no screen shows a bare centred grey line.
   *(S03-1, S04-2, S06-2, S12-2, S13-3)*
2. **Settings/menu list group** (`ListTile` + leading icon + chevron +
   optional subtitle, section headers on the tile keyline, a danger-zone
   variant in `error` colour). Replace the `TenturaCommandButton` stacks in
   `settings_screen.dart`, `profile_body.dart` and `profile_view_body.dart`.
   Acceptance: every row is 48 dp or taller; destructive rows are separated
   and red; Debug is gated on `kDebugMode` or a QA flag.
   *(X-02, X-16 partly, S19-6, S08-3)*
3. **Avatar contrast + badge system.** Initials in `onSecondaryContainer`
   on `secondaryContainer`; a stacked-avatar ring; a single status-badge
   widget with a tooltip and semantics label (eye / link / ring). Remove
   the oversized eye on other profiles.
   *(S06-3, S10-1, S10-5, S16-4, S17-5, S15-3, S01-8)*
4. **Theme audit of state colours.** `switchTheme` off state (outline
   track/thumb), checkbox outline `onSurfaceVariant`, MD3 disabled
   button tokens, `Archive` as a primary text button. Rating tiles choose
   their text colour by fill luminance. *(X-05)*
5. **Text-field decoration.** Use the design-system outlined/filled
   `InputDecorationTheme` with floating labels, `helperMaxLines: 2`, and
   counters only above 80 % of the limit. Adopt it on 09 and 11.
   *(X-14, S09-1, S11-1, S11-5)*
6. **Icon-action tooltips + labels sweep.** Every `IconButton` in app bars
   gets a tooltip. Theme segments get labels ("System / Light / Dark"). The
   Map/Text toggle keeps its labels on compact. *(X-04)*

### Phase 2 — shell, navigation and layout (clears X-01, X-10, X-11, X-13)

7. **Keep the rail on pushed routes at expanded width.** Render
   Following / Rejected / Updates / Edit profile / Other profile inside the

## Status (2026-09-28)

Implemented on branch `fix/ux-audit-2026-09-27`, one commit per plan unit
(client 7.24.6). Verified after each unit by re-running `shots.js` on the
affected screens at both widths and by the relevant widget tests. On the
final full client run, 4250 tests passed and 5 failed. All 5 failures also
occur on the pre-audit commit `7edde2ff8` in this environment
(`beacon_fact_card_gql_test` codegen freshness, two
`constellation_viewport_chrome_test` cases, `direct_v2_schema_overlay_test`
#181, `forward_candidate_context_di_test`). Custom lints went down
from 27 to 26, and the baseline was lowered to match.

Two root causes turned up during the work that the audit had not named:

- **`TenturaUnderlineTabs` never drew its active indicator.** The indicator
  was a height-only `SizedBox` in a `Column`, so it laid out at zero width.
- **`ColorScheme.outline` is the light hairline border.** Material 3 draws
  unselected switches and checkboxes with it, so they looked disabled.
  `ListTile` desktop density also trimmed the title gap by 4 dp, which put
  row text off the divider keyline.

**Kept on purpose.** A test or spec pins each of these, so the audit
suggestion was not applied:

| Finding | Why it stays |
|---|---|
| S14-2 always-on Chat split | The split is gated on the viewer having discussion rows; an empty pane for a non-participant is worse (`beacon_view_room_split_contract_test`). |
| S07-1 auto-fit My field on load | Explicitly "no auto-fit on reload" (`constellation_viewport_chrome_test`); fitting also drops into the overview LOD and hides pin badges. Left to the constellation remediation plan. |
| S12-3 child-requests keyline | The section sits on the HUD text keyline by design (issue #167 test). Only its floating action was fixed. |
| S01-6 own starred face pile | The author's own pile is pinned (`beacon_request_preview_identity_test`). |
| S10-2 tonal Trust | The action-policy test pins one `FilledButton` per profile; navigation rows now separate it from links. |
| S12-2 green "No open items" | The tone is phase-derived (`toneForYouEmptyFallback`). |
| S06-5 graph icon on My people | Pinned by `friends_app_bar_actions_test`. |
| S02-2 own outcomes in For you | A request-attention spec question (§6/§8), not a layout one. |

**Deferred.** These need data or a product decision:

- S05-1: Updates rows naming their Request. Receipts carry no Request title; this needs a server payload field.
- S02-8 / S08-5 / S10-7: two-pane layouts for lists and profiles on expanded windows.
- S16-6 / S17-6: graph scale-up on sparse canvases.
- S21-2: device-key labels instead of key hashes. The client has no device metadata.
- The Debug entry in Settings stays visible, grouped under App. Staging QA may rely on it, and there is no build flag to gate it.
